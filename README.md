# Bonvoy L4/L5 Checker

신한 메리어트 본보이 카드의 **포인트 적립 상세내역 엑셀**을 브라우저에서 분석해, 메리어트 호텔 결제가 특별적립(국내 **L4** / 해외 **L5**)으로 처리되었는지 확인하는 도구입니다.

- 라이브: <https://shinhan-bonvoy-points-checker.vercel.app>
- 저장소: <https://github.com/wonsik99/shinhan-bonvoy-points-checker>
- 기준 카드: 메리어트 본보이™ 더 베스트 신한카드
- 분석: 사용자 브라우저 안에서만 (서버 업로드 없음)
- 판정: 결정적 규칙 기반 · 사용자 앱 경로에 LLM 없음

> 결과는 카드사 문의를 돕는 참고 자료입니다. 화면에는 `누락 의심`과 `확인 필요`만 표시하며, 실제 적립을 확정하거나 보장하지 않습니다.

## 주요 기능

- 신한카드 포인트 적립 상세내역 `.xlsx` / `.xls` 분석
- 국내 메리어트 L4 · 해외 메리어트 L5 특별적립 확인
- 실제 적립과 예상 포인트 차이 계산
- 호텔·가맹점명 정규화 및 Marriott alias 대조
- 해외 거래의 `해외가맹점명` 우선 처리
- `포함` / `제외` / `모르겠음`으로 확인 필요 거래 직접 판정
- 카드사 문의 문구 생성·복사 · 전화/1:1문의/공유 채널 연결
- 앱이 놓친 거래를 사용자가 메리어트로 지정하는 보정
- 선택적 익명 피드백 · 파싱 실패 진단 제보

## 사용자 흐름

1. 신한카드 고객센터(1544-7000)에 포인트 적립 상세내역 엑셀을 요청합니다.
2. 파일을 앱에 업로드합니다.
3. 브라우저에서 거래를 분석합니다.
4. `누락 의심`과 `확인 필요` 항목을 검토합니다.
5. 필요한 거래를 포함하거나 제외합니다.
6. 생성된 문의 문구를 복사해 신한카드에 접수합니다.

앱·홈페이지에서는 해당 엑셀을 받을 수 없고, 고객센터 전화로만 발급됩니다.

## 지원 파일 형식

- 헤더 2행 + 거래 1건당 2행 인터리브 형식
- 제목 행이 헤더 앞에 있는 형식
- 일반적인 1행 1거래 형식
- 해외 거래에서 채널명 `가맹점명` 대신 `해외가맹점명` 우선
- Excel 날짜 serial · 신한 컬럼 별칭 정규화

지원되지 않는 레이아웃은 진단 정보와 함께 오류를 보여 주며, 복사하거나 선택적으로 제보할 수 있습니다.

## 판정 기준

### 적립 등급

`포인트종류상세` 컬럼의 등급 코드를 사용합니다.

| 코드 | 의미 | 적립 기준 |
|---|---|---:|
| L1 | 기본 적립 | 1,000원당 1P |
| L2 | 해외 매출 적립 | 1,000원당 3P |
| L3 | 특별 적립 업종 | 1,000원당 3P |
| L4 | 국내 메리어트 결제 | 1,000원당 5P |
| L5 | 해외 메리어트 결제 | 1,000원당 5P |

현재 기준은 **메리어트 본보이™ 더 베스트 신한카드**입니다. 더 클래식은 메리어트 적립 기준이 달라 아직 미지원입니다.

### 누락 의심으로 분류되는 패턴

메리어트 호텔로 분류되고 확신도가 충분하며, 아래 정상 누락 패턴과 양수 차이가 함께 있을 때 `누락 의심`으로 표시합니다.

- 국내 메리어트: `L1 → L4`
- 해외 메리어트: `L2 → L5`

애매한 경우는 `확인 필요`로 남깁니다.

## 개인정보와 데이터 흐름

### 엑셀 파일

업로드한 파일은 `File.arrayBuffer()`와 SheetJS로 브라우저 안에서만 읽습니다.

- 엑셀 원문을 서버로 올리지 않음
- 결제금액·거래일자·카드번호·포인트 상세를 서버로 보내지 않음
- 파싱·정규화·분류·포인트 계산은 클라이언트에서 수행
- 파일을 바꾸거나 초기화하면 이전 분석 상태를 버림

### 선택적 피드백 수집

`NEXT_PUBLIC_APPS_SCRIPT_URL`이 있을 때만, 사용자가 명시적으로 제보를 눌렀을 때 Google Apps Script로 전송합니다.

`내 판단으로 서비스 돕기`에서 보내는 값:

- 가맹점명 · 정규화 호텔명 · 사용자 판단
- 앱 판정 상태·확신도 · 포인트 등급 코드
- 탭 단위 익명 세션 ID

파싱 실패 제보는 진단 텍스트만 보냅니다. 파일·금액·일자·카드번호·원본 행은 보내지 않습니다.

## 익명 피드백 수집기 설정

1. Google Sheet에 Apps Script를 엽니다.
2. [`google-apps-script/Code.gs`](google-apps-script/Code.gs)를 붙여넣습니다.
3. 웹 앱으로 배포합니다 (실행: 본인 · 액세스: 모든 사용자).
4. Vercel에 환경변수를 등록합니다.

```env
NEXT_PUBLIC_APPS_SCRIPT_URL=https://script.google.com/macros/s/배포ID/exec
```

5. 재배포합니다. env가 없으면 수집은 no-op이고, 파싱 실패는 복사 fallback을 씁니다.

이 URL은 `NEXT_PUBLIC_`이라 **비밀값이 아닙니다**. 요청 검증·길이 제한·중복 억제·일일 한도·모니터링을 함께 운영하세요. 피드백은 집계·수동 검토 후에만 규칙 후보로 씁니다.

```bash
npm test             # Vitest

npm run lint && npm run build
```

## 프로젝트 구조

```text

lib/                 파싱 · 정규화 · 분류 · 분석 · 피드백
```

## 배포

Vercel 정적 배포입니다. GitHub 연동 시 push/PR로 Preview·Production이 올라가고, CLI로는 `vercel --prod`를 씁니다.

배포 전 `npm test` · `npm run lint` · `npm run build`를 권장합니다. 수집기 URL을 바꿨다면 Preview에서 CSP와 제보 버튼을 확인하세요.
