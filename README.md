# Bonvoy L5 Checker

신한 메리어트 본보이 카드의 **포인트 적립 상세내역 엑셀**을 브라우저에서 분석해, 메리어트 호텔 결제가 특별적립 등급으로 처리되었는지 확인하는 도구입니다.

- 라이브 서비스: <https://shinhan-bonvoy-l5-checker.vercel.app>
- 저장소: <https://github.com/wonsik99/shinhan-bonvoy-points-checker>
- 기준 카드: 메리어트 본보이™ 더 베스트 신한카드
- 분석 위치: 사용자의 브라우저
- 판정 방식: 결정적 규칙 기반
- LLM: 사용자 앱 경로에서 사용하지 않음

> 결과는 카드사 문의를 돕는 참고 자료입니다. 화면에는 `누락 의심`과 `확인 필요`만 표시하며, 실제 적립 여부를 확정하거나 보장하지 않습니다.

## 주요 기능

- 신한카드 포인트 적립 상세내역 `.xlsx` / `.xls` 분석
- 국내 메리어트 결제의 L4, 해외 메리어트 결제의 L5 특별적립 확인
- 실제 적립 포인트와 예상 포인트의 차이 계산
- 호텔명·가맹점명 정규화 및 메리어트 호텔 alias 대조
- 공식 Marriott 호텔 seed와 영문·한글 alias를 이용한 결정적 대조
- 해외 거래의 `해외가맹점명` 우선 처리
- 사용자가 `포함`, `제외`, `모르겠음`으로 확인 필요 거래를 직접 판단
- 카드사 문의 문구 생성·복사
- 앱이 놓친 거래를 사용자가 메리어트로 지정하는 보정 기능
- 선택적으로 익명 피드백과 파싱 실패 진단 정보 수집

## 사용자 흐름

1. 신한카드 고객센터에 포인트 적립 상세내역 엑셀을 요청합니다.
2. 파일을 앱에 업로드합니다.
3. 브라우저에서 거래를 분석합니다.
4. `적립 누락 의심`과 `확인 필요` 항목을 검토합니다.
5. 필요한 거래를 포함하거나 제외합니다.
6. 생성된 문의 문구를 복사해 신한카드에 문의합니다.

신한카드 앱이나 홈페이지에서 해당 엑셀을 바로 내려받을 수 없는 경우가 있어, 고객센터에 발급 가능 여부를 확인해야 할 수 있습니다.

## 지원 파일 형식

실제 신한카드 적립 상세내역은 다음과 같은 변형을 지원합니다.

- 2개의 헤더 행과 거래 1건당 2개의 데이터 행이 번갈아 나오는 형식
- 제목 행이 헤더 앞에 있는 형식
- 일반적인 1행 1거래 형식
- 해외 거래에서 채널명인 `가맹점명` 대신 실제 호텔명이 있는 `해외가맹점명` 우선 사용
- Excel 날짜 serial 값과 신한카드 컬럼 별칭 정규화

지원되지 않는 레이아웃은 친절한 오류와 제한된 진단 정보를 보여주며, 사용자가 직접 복사하거나 선택적으로 제보할 수 있습니다.

## 판정 기준

### 적립 등급

`포인트종류상세` 컬럼의 등급 코드를 사용합니다.

| 코드 | 의미 | 적립 기준 |
|---|---|---:|
| L1 | 기본 적립 | 1,000원당 1P |
| L2 | 해외 매출 적립 | 1,000원당 3P |
| L3 | 특별 적립 업종 | 1,000원당 3P |
| L4 | 국내 메리어트 결제 | 1,000원당 5P |
| L5 | 해외 메리어트 결제 | 1,000원당 5P |

현재 기준은 **메리어트 본보이™ 더 베스트 신한카드**입니다. 더 클래식 카드는 메리어트 적립 기준이 다르므로 아직 지원하지 않습니다.

### 누락 의심으로 분류되는 패턴

메리어트 호텔로 분류되고, 가맹점 분류 확신도가 충분하며, 다음의 정상 누락 패턴과 양수 차이가 함께 확인될 때 `누락 의심`으로 표시합니다.

- 국내 메리어트: `L1 → L4`
- 해외 메리어트: `L2 → L5`

그 외 애매한 경우는 자동으로 확정하지 않고 `확인 필요`로 남깁니다.

## 개인정보와 데이터 흐름

### 엑셀 파일

업로드한 파일은 `File.arrayBuffer()`와 SheetJS를 통해 브라우저 안에서만 읽습니다.

- 엑셀 원문을 서버로 업로드하지 않음
- 결제금액·거래일자·카드번호·포인트 상세를 서버로 전송하지 않음
- 파싱·정규화·분류·포인트 계산을 클라이언트에서 수행
- 파일을 새로 선택하거나 초기화하면 이전 분석 상태를 버림

### 선택적 피드백 수집

환경변수 `NEXT_PUBLIC_APPS_SCRIPT_URL`이 설정된 경우에만 사용자가 명시적으로 제보를 눌렀을 때 Google Apps Script로 전송합니다.

`내 판단으로 서비스 돕기`에서 보내는 값:

- 가맹점명
- 정규화된 호텔명
- 사용자 판단
- 앱의 판정 상태와 확신도
- 포인트 등급 코드
- 탭 단위 익명 세션 ID

파싱 실패 제보에서는 앱이 만든 진단 텍스트만 보냅니다. 파일 자체, 거래금액, 거래일자, 카드번호, 전체 원본 행은 보내지 않습니다.

## 익명 피드백 수집기 설정

수집기는 기본적으로 비활성화되어 있으며, 설정하면 Google Sheet에 익명 피드백이 쌓입니다.

1. 새 Google Sheet를 만들고 Apps Script 편집기를 엽니다.
2. [`google-apps-script/Code.gs`](google-apps-script/Code.gs)의 내용을 붙여넣습니다.
3. 웹 앱으로 배포합니다.
   - 실행 계정: 운영자 본인
   - 액세스 권한: `모든 사용자(Anyone)`
4. 발급된 웹 앱 URL을 Vercel 환경변수에 등록합니다.

```env
NEXT_PUBLIC_APPS_SCRIPT_URL=https://script.google.com/macros/s/배포ID/exec
```

5. 환경변수를 적용해 다시 배포합니다.

환경변수가 없으면 수집 요청을 보내지 않고, 파싱 실패 제보는 진단 정보 복사 방식으로 사용할 수 있습니다.

### 수집기 운영 주의사항

이 URL은 `NEXT_PUBLIC_` 환경변수로 브라우저에 전달되므로 **비밀값이 아닙니다**. 사용자는 번들 또는 브라우저 네트워크 도구에서 URL을 확인할 수 있고, 제3자가 직접 HTTP 요청을 보낼 수도 있습니다. `no-cors`는 브라우저의 응답 접근을 제한할 뿐 직접 요청을 막는 인증 기능이 아닙니다.

따라서 운영 환경에서는 다음을 함께 고려해야 합니다.

- Apps Script에서 요청 타입·필드·enum을 엄격하게 검증
- 본문과 필드 길이 제한
- 동일 요청 중복 차단
- 일일 전체 쓰기 한도와 운영자 중단 스위치
- Apps Script 실행/Sheet 쿼터와 이상 요청 모니터링
- 익명 피드백을 규칙으로 반영하기 전 집계·수동 검토

수집기를 서버형으로 확장하더라도 엑셀 파일과 포인트 계산까지 서버로 옮길 필요는 없습니다. 필요할 때 피드백 수집 ingress만 별도 rate limit API 뒤로 이동할 수 있습니다.

## 개발 환경

### 요구 사항

- Node.js 20 이상 권장
- npm

### 설치 및 실행

```bash
npm install
npm run dev
```

개발 서버는 기본적으로 <http://localhost:3000>에서 실행됩니다.

### 검증 명령

```bash
npm test                 # Vitest 단위 테스트
npm run test:coverage    # 커버리지와 하한선 검증
npm run test:e2e         # Playwright 브라우저 통합 테스트
npm run lint             # ESLint
npm run build            # 프로덕션 정적 빌드
npm run fixture          # docs/_local/sample.xlsx 생성
```

`npm run fixture`가 만드는 파일은 로컬 검증용이며 `docs/_local/`은 커밋하지 않습니다.

## 프로젝트 구조

```text
app/                    Next.js App Router 페이지와 레이아웃
components/             업로드, 진행 단계, 결과 표, 문의 UI
lib/                    파싱, 정규화, 분류, 분석, 피드백 로직
lib/__tests__/          Vitest 테스트
rules/                  Marriott 브랜드·호텔 alias·가맹점 규칙
rules/cardProfiles.ts   카드별 적립 프로필
types/                  공용 TypeScript 타입
google-apps-script/     선택적 Google Sheets 수집기
scripts/                로컬 fixture 생성 스크립트
next.config.ts          CSP와 보안 응답 헤더
```

## 배포

이 프로젝트는 Vercel에서 정적으로 배포합니다.

### Git 연동 배포

Vercel 프로젝트에 GitHub 저장소를 연결하면 기본 브랜치 push 또는 pull request에 따라 Preview/Production 배포가 실행됩니다. 실제 배포 브랜치와 환경변수는 Vercel 프로젝트 설정에서 확인합니다.

### CLI 배포

프로젝트가 Vercel CLI에 연결된 상태라면 다음 명령으로 Production 배포를 실행할 수 있습니다.

```bash
vercel --prod
```

배포 전에는 최소한 `npm test`, `npm run lint`, `npm run build`를 실행하고, `NEXT_PUBLIC_APPS_SCRIPT_URL`을 변경했다면 CSP와 제보 버튼 동작을 Preview에서 확인합니다.

## 현재 제한과 로드맵

- 더 클래식 카드 프로필 및 카드 선택 UI
- 피드백 집계·후보·수동 검토를 위한 운영자 도구
- Marriott 호텔 alias 데이터 확장
- 수동 검증 alias가 충분히 쌓일 경우에만 선택적 비공개 alias 조회 API 검토

사용자 앱의 판정 경로에는 LLM을 추가하지 않습니다. 비공개 alias API를 도입하더라도 파일 전체를 서버로 보내지 않고, 사용자가 동의한 최소한의 미매칭 가맹점명만 별도 조회하는 방식으로 검토합니다.

## 면책

- 이 서비스는 Marriott, Marriott Bonvoy 또는 신한카드의 공식 서비스가 아닙니다.
- 결과는 카드사 문의를 돕기 위한 참고 자료입니다.
- 실제 적립 여부는 카드사 내부 가맹점 업종코드, 매입 경로, 카드 약관과 처리 시점에 따라 달라질 수 있습니다.
